# E2E 刮削测试执行标准

> **目标**：每一号测完都能发现缺口、修映射、改逻辑，最终让合并刮削在「字段全、中文优先、女优/标签准、封面合规、入库可读、女优资料/头像齐」上接近完美。  
> **用法**：开测前读一遍检查清单；测完按「反问 → 记案例 → 补标准」闭环更新本文。  
> **脚本**：`apps/api/_gap_reports/_e2e_one_code.py`  
> **样本**：`apps/api/_gap_reports/e2e_prefix_sample.json`  
> **单号报告**：`apps/api/_gap_reports/e2e_one_by_one/<CODE>.json`

---

## 0. 怎么跑

```text
cd apps/api
.venv\Scripts\python.exe -u _gap_reports\_e2e_one_code.py --index=N --write --fix-maps
# 或指定番号
.venv\Scripts\python.exe -u _gap_reports\_e2e_one_code.py --code=XXXX-000 --write --fix-maps
# 对照正式路径（会再拉一遍源，慢）
.venv\Scripts\python.exe -u _gap_reports\_e2e_one_code.py --index=N --write --refetch-on-write
```

约定：

1. **一号一测**：说「下一个」只跑下一个样本，测完汇报，再等人说继续。
2. **默认 `--write`**：骨架 → 正式入库；本地只留 **一张** `poster.jpg` + 分行易读 NFO；写完再跑 **step6 女优资料+头像**（可用 `--skip-actress-assets` 跳过）。
3. **默认 `--fix-maps`**：可自动补女优/标签别名，但必须人工核对，禁止错绑。
4. **多人女优强制查别名**：合并结果 **≥2 人** 时，必须核对是否「同人别名被重复列出」（对照标题人数、FANZA/正规源）；别名簇要收敛成标准名，**人数以同人去重后为准**（案例 SDMUA-008：表面多人实为 3 人）。
5. **逐源探测并发**：`fetch_each_source` 按刮削策略 `adaptiveWorkers`（0=全开）线程池并发；日志按完成顺序打印，报告仍按目录源序。只测面板里**已启用**的源（关闭的站不会出现）。
6. **提速（默认）**：只拉源 **一遍**。step2 用探测结果 `_merge_got`+LLM；step3 `--write` 复用合并详情写 NFO/封面/向量（`reuse-merge`）。`--refetch-on-write` 才第三次全网拉源。`--write` 时与拉源并行预热 embed 模型。
7. **封面拉图**：候选按 DMM 优先；DMM 空图时立刻回落 javbus（勿先撞完一串 DMM 变体）；javbus/seejav 单次超时即换 URL，不再叠 seejav/sehuatang 一串 Referer。
8. 测完必须：**更新本文「案例账」+ 必要时改检查项/反问项**。

## 1. 检查哪些（强制清单）

每一号至少过完下列 8 大块。任一块 FAIL 都要记 issue，能修当场修。

### 1.1 各源解析健康

| 检查 | 通过标准 | 失败时 |
|---|---|---|
| 源是否应按区命中 | 有码区：javbus/dmm/libredmm/jav321/r18dev 等应有结果；明确不适用（mgstage/carib）可 SKIP | 不该 FAIL 的源 FAIL → 修解析/搜索/超时 |
| 错页拒用 | 标题与定稿/女优明显无关（如 ABF 命中ジュポニカ）→ 该源剧情/标签/女优不进合并与 `--fix-maps`；站点品番标错时靠身份门禁 | 错页剧情被 LLM 二次翻译；错页女优写进映射表 |
| 字段非空 | `title`、`poster`、`actors`（若源站有）、`studio`、`date` 尽量齐 | 源站有但我们空 → 解析 bug |
| 标题污染 | 无「会员登入 / Cloudflare / 404」等垃圾标题 | 拒用该源标题，修入口过滤 |
| 女优清洗入口 | 无半截 `（`、半角假名未折叠、img title 误吸 | 修 `_clean_actors` / 源解析 |
| 标签污染 | 标签里不应出现女优名、片商名、登录文案、番号前缀、促销词 | drop 映射或解析排除 |
| 预期失败 | 记入 `expected_fail`，不计入「源解析 FAIL」；**老片（`year<2015`）** 源报「未找到/搜索无结果」自动记预期失败 | 勿把预期失败当回归 |
| **覆盖未收录（miss）≠ 技术失败（fail）** | 源报 `未找到 / 搜索无结果 / 番号格式无效` = 源站确无此片，属**覆盖 miss**，**不计入** `parse` 失败；只有 `HTTP / 超时 / 番号不符 / 标题门禁` 等才计**技术 fail** | 把 miss 当解析 bug 去修（白费功夫） |
| **无效骨架号** | 全部真实源均未收录、仅 dmm 回显番号 → `title==番号` 且无女优/片商/剧情 ⇒ 标 `invalid_skeleton`，**跳过写盘**且**不计入准确率分母**（案例 JAN-025 / OPEN-028） | 把骨架号当回归失败 |

**输出**：报告里 `parse.ok_ids / fail / miss / skip`。**准确率口径**：`judgeable = 总数 − invalid_skeleton − errors`，只用技术 `fail` 计失手。

### 1.2 合并是否选了最优

对比「各源候选分」与「最终 merged」：

| 字段 | 最优原则（现行） | 反例 |
|---|---|---|
| 标题 | **字段优先级链**（默认中文源前置：airav→iqqtv→…）取首个合格非空；质量分低于最优 35 则跳过；拒绝垃圾/过短；中文标题去掉「…。 2」类孤立系列尾号；**烂机翻**回退后只译已校验 `titleJa`（策略 `llmTranslateOnJunk`） | 有 miss_av/iqqtv 中文却落了 airav 日文；尾号像脏页码；TCD-226 机翻压过官名；错页日文被 LLM 二次翻译 |
| 剧情 | 同字段链（中文前置）+ 标题兼容过滤错页；剔除站点广告/水印；**不得串入其他女优名**；LLM 只译 `overviewJa` | 日文水印伪剧情；ABF-005 ジュポニカ错页剧情；STAR-795 串台松冈千菜 |
| 女优 | 身份门禁清空错页源后再投票；无共识时优先**与定稿标题同源**；**≥2 人时必查别名重复** | 错页多人女优压过正确单人；别名未收敛 |
| 片商 | 字段链官方前置（dmm/mgstage/r18dev） | 空或错成系列名 |
| 日期/年 | 字段链官方前置 | 空或明显错年 |
| 封面 URL | 字段链官方 CDN 前置；mono/pl 实图优先于 digital 空图 | 选了 NOW PRINTING / 空图 |
| 标签 | 错页源不进；简体收敛、同义合并、无女优名；**合并后不得残留任何通用噪声**（番号前缀/促销词/年代元标签） | 繁简双份；女优名进 genre；错页「高中生」；`NDRA`/`BIGセール第2弾` 类残留 |

**输出**：`fieldSources`、`expected_winners` 与 `merged` 对照；不一致写 issue。

### 1.3 女优映射

> **身份优先，不强制中文**：多源异写必须合并为**一个真实身份**（别名/繁简/假名折叠 → 同一展示名）。展示名可以是日文官名或中文通行写法；**未入中文映射表不算 FAIL**（E2E 仅软提示）。硬失败只看：错人、同人未收敛导致人数虚高、映射错绑。
>
> **铁律（多人）**：只要最终女优 **≥2**，先问「是不是同人别名重复？」再问「少没少人」。  
> 正规源（FANZA / JavLibrary 等）与标题里的人数是标尺；库把曾用名全挂上 ≠ 真实人数。  
> 标题用 `×` 点名时，**点名人数优先于演员栏投票**（案例 SDMU-088：栏里 2 人、标题 4 人）。  
> **映射表铁律（别名链）**：映射表是**单趟**查表（`polish_actress_names` 只查一次）。禁止 `A→B` 且 `B→C` 的链式别名——单趟会把 `A` 停在中间名 `B`，令同一个人出现两种标准名（案例 MIAE-146：`春菜はな→春菜华→春菜花`）。别名**必须直指最终 canon**；改表后跑 `_normalize_actor_aliases.py` 扁平化（幂等，`chains=0` 才算干净）。

| 检查 | 通过标准 |
|---|---|
| **别名去重** | 跨源异名收敛到同一身份主名后，**一人只出现一次**；表面 6～8 名常为 2～3 人的别名簇 |
| **别名链扁平化** | 表内不得存在 `A→B→C` 链，`A` 必须直指最终 canon。E2E 报 `映射未完全收敛: polished=[…] → canons=[…]` 即此病。修法：`_normalize_actor_aliases.py --apply` |
| **canon 选主名** | 别名簇的 canon 取**主名**（minnano-av 主名 / 中文源通行写法），勿把「中华AV 别称」当 canon（案例 SNOS-114：别称 `水原聖子` → canon 改回主名 `南羽琉`） |
| **艺名变更** | 改名/移籍产生的新旧名是**同一人**，必须收敛为同一标准名（案例：`美谷朱音`=美谷朱里；`真矢みつき`=神谷充希）；见陌生新名先查是不是旧名换了写法 |
| 人数对齐 | 去重后人数 ≈ 标题明示（如「3人の痴女」）或 FANZA 主演栏 |
| 跨源异写 | `宮沢ゆかり` / 异写 → **同一身份展示名**（有表用 canon，无表折叠字形；不强制中文） |
| 禁止错绑 | 不同人不得共用一条 canon；**同人别名必须收敛**（案例：真矢みつき=神谷充希，勿拆成两人） |
| 禁止盲目并集 | 多源按**投票共识**合并（源≥5 需≥3 票），再经别名映射去重（SDMUA-008） |
| auto-fix 安全 | 只允许 NFKC 同形绑已有 canon；**禁止** `key→{name:key}` 自占位写表（错页名会永久污染）；未入表仅软提示，不挡 checklist |
| 精选集 | 总集篇多人：覆盖主宣女优；勿用错误 content_id；同样先做别名去重 |

### 1.4 标签映射

| 检查 | 通过标准 |
|---|---|
| 繁→简 | `女同性戀→女同`、`無毛→无毛`、`4小時以上作品→4小时以上作品` |
| 同义折叠 | `中出し→中出`、`女優ベスト→女优精选` |
| **通用噪声自动 drop** | 促销词（`セール`/`％オフ`/`クーポン`/`キャンペーン`/`期間限定`/`第N弾`/`セット商品`/`アウトレット`…）、**番号前缀**（`NDRA`/`NDRA117`/`WAAA-540`；白名单 `SM/VR/OL/POV/JK/AV/NTR/BD/DVD/HD/FHD/UHD` 除外）、**年代元标签**（`2010年代前半(DOD)`/`2020年代前半（DOD）`…）统一由 `tag_is_noise` 判定，**无需逐条补表** |
| **繁简/异体折叠兜底** | 表里只登记一种写法时，`_fold_variant` + `_variant_index`（同时索引键与标准名）自动把异体折叠到标准名——解「`义母`/`義母`/`繼母`/`継母`」多重分裂 |
| **合并后字形归一去重** | 合并主循环与 `_clean_tags` 都**先 `_fold_variant` 折叠字形、再按折叠键去重**；否则同一语义的异体会双份留在 NFO（`穿衣幹砲`+`穿衣干炮`、`恋爱`/`恋愛`/`戀愛`、`連褲襪`+`连裤袜`、`泳裝`+`泳装`、`黑人演員`+`黑人演员`）。回归探针：`_probe_tag_variants.py` |
| 折叠表覆盖 | `_TAG_VARIANT_PAIR_TEXT` 现 627 对；缺对时按「繁体独有字」补（`幹干 砲炮 褻亵 著着 無无 竜龙 歳岁 …`），**不要**补「简繁同用字」（如 `著→着` 仅在 `穿著` 词内安全，已按此判断收录） |
| **折叠只用于输出侧** | `_clean_tags(tags, *, fold=True)` 默认折叠；但**源侧明细必须 `fold=False`**——源侧标签喂给 `_score_tags` 评分，提前折叠会毁掉「繁体惩罚」，反转选源（案例 ACHJ-078） |
| drop | 女优名、噪声、过短无意义词 |
| 合并结果 | NFO `<genre>` 与向量 `类型：` 一致且已收敛；**全样本 merged 命中通用噪声必须为 0** |

> 回归工具：`apps/api/_gap_reports/_probe_noise_rules.py`（不联网）。断言噪声规则、繁简折叠、女优折叠，并扫描全部 `e2e_one_by_one/*.json` 的 raw/merged 标签；**merged 残留数必须为 0，否则脚本以非 0 退出**。  
> 另一回归工具：`apps/api/_gap_reports/_probe_tag_variants.py`（不联网）。断言「合并标签字形归一去重」12 条用例（繁简/异体/日文旧字），任一失败以非 0 退出。

## 2. 测完必须反问自己（强制）

每号写报告前，逐条回答（写进案例账「反思」栏）：

1. **若只有一个源成功，合并还会对吗？** 会不会被错误源带偏？
2. **中文源失败时**，我们是合理降级日文，还是其实能修好中文源？
3. **女优名单**：若 ≥2 人，是否先查过**别名重复/同人簇**？去重后人数是否与标题（如「3人」）或 FANZA 一致？精选集是否误用了别的 content_id？
4. **自动补映射**有没有把 A 绑成 B，或把同人拆成两人？需要回滚吗？
5. **标签**是否还有繁体双份、女优名、片商名？
6. **封面**是否真的下到了、裁剪是否符合该区策略、目录是否只有一张图？
7. **NFO** 打开肉眼是否好读？剧情有无广告尾巴？
8. **女优资产**：头像是否本地可读？生日→年龄、身高/罩杯/生涯是否合理（错人资料立刻修）？
9. **这次的 FAIL** 是「源站本来没有」还是「我们解析/合并/下载有 bug」？后者必须开修。
10. **标准文档缺了哪一条？** 立刻补进第 1/2/3 节。
11. **下一号**是否还适合用同一套预期源列表？

## 3. 怎么优化（优先级）

发现问题时按此顺序动手，避免只改样本、不改系统：

### P0 — 正确性（立刻修）

- 错绑女优 / 错 content_id / 垃圾标题进库
- 空图当封面导致入库 FAIL
- 中文标题/剧情明明有却被日文压过
- 女优名进标签

### P1 — 映射与清洗

- `apps/maps/scrape/actors.zh-CN.json` 纠错、补别名（人工确认）
- `apps/maps/scrape/tags.zh-CN.json` 繁简/同义/drop
- 剧情广告尾巴剥离（DMM コンビニ受取 等）
- 半截括号、半角假名、NFKC

### P2 — 源解析

- 单源字段缺失但源站页面有 → 修 `scrape_details/<source>.py`
- 搜索无结果但番号存在 → 搜索词/备用域名/Flare
- 与 MDCS 同号字段对拍（`.refs/mdcs`）

### P3 — 体验与稳健

- 封面下载超时重试/多候选
- NFO 格式、单图策略、策略面板默认值
- E2E 脚本：把新检查项自动化进 checklist
